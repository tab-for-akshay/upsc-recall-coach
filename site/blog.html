A study coach that remembers you

UPSC aspirants practise dozens of syllabus topics over months. Most practice apps forget them when the tab closes, so every session opens on the same generic list. A good human coach does the opposite: “you keep missing the C4 pathway and soil CEC, start there today.” UPSC Recall Coach is our attempt at that coach, for the Total Recall hackathon (Walrus × Tatum), track Smart Agents for Real Life.

What it does

  1. Quiz. Pick one of 26 topics across Agriculture, Botany and General Studies. Four questions come from a bank of 130 that we wrote and then checked one by one against a cited source (the full log is CHECKS.csv). The concepts you missed before come first. You can also ask for fresh AI-written questions: one model writes six, a second model re-solves them blind, and any it disagrees with are dropped. If a question still looks wrong, flag it and it does not count.
  2. Remember. The result becomes one short memory written by code: date, topic, score, missed concepts, language. It is stored with Walrus Memory on Sui mainnet, in the learner's own namespace.
  3. Recall and plan. Next time, the app recalls the learner's memories and builds today's plan in plain code: topics due for review first (they come back after 1, 2, 4 or 7 days depending on recent accuracy), then the weakest, the concepts to fix, videos for them, and one topic never practised. A coach note puts that in three sentences, using only those computed facts.
  4. Prove. A receipts panel reads Sui mainnet through Tatum and shows each memory as a Walrus Blob object: object ID, creating transaction, size and storage epochs, with explorer links.

How it uses Walrus Memory

We use the MemWal SDK (@mysten-incubation/memwal) in its default relayer mode. Each quiz result is one remember call; we wait for the job and get back the Walrus blob ID. The relayer SEAL-encrypts the memory before it is uploaded to Walrus, so the bytes stored are ciphertext; on recall it decrypts them for our delegate key. Each learner has a namespace (coach-<learner-id>), so one learner's history never mixes with another's.

The model never decides what you know. Memories carry machine-readable tags ([topic:…] [score:3/4] [lang:hi]) written by code, and the planner parses those tags. The only text that comes from a quiz, the missed concept labels, has brackets stripped, so nobody can inject a fake tag.

Learner IDs are minted and signed by the server. Only signed IDs can write, so nobody can add memories to someone else's history by guessing a name. The public demo learner is read-only: “Load demo learner” gives each visitor a private copy that reads the nine seeded demo results plus that visitor's own quizzes.

How it uses Tatum

Tatum's Sui mainnet endpoint is gRPC, at sui-mainnet-grpc.gateway.tatum.io:443. We connect with the Sui TypeScript SDK's gRPC client and the Tatum API key as metadata, then make three calls: getChainIdentifier; getObject on the MemWal account object (type, version, owner, delegate keys); and listOwnedObjects filtered to the Walrus blob::Blob type. Each Blob object carries its blob ID as a u256; the Walrus blob ID is that number's little-endian bytes in base64url. We convert it, match it to the memory we recalled, and show the object, the transaction that created it, its size, the epoch it was certified and the epoch its storage ends. A unit test pins the conversion against a real mainnet blob. A save shows its receipt straight away, and the panel re-checks all of them on demand.

What a receipt proves, and what it does not: it proves the write happened on Sui mainnet, who owns it and how long Walrus keeps it. It cannot show the text, because the blob is encrypted. The text beside each receipt is what the SDK decrypted from that blob ID on recall.

How it learned over time

The plan page shows the same day twice: without memory, where everyone gets the most-recommended topics, and with your Walrus memory. On the demo learner, memory moves Soil science, Plant physiology and Agronomy to the top (recent scores of 38%, 38% and 50%), lists the concepts missed (the C4 pathway and cation exchange capacity were each missed twice) and links a video for each. In one test run we took a Plant physiology quiz as a demo copy and scored 1 out of 4. The plan reordered at once: Plant physiology moved to first place and came due for review the next day, and the coach note named the C4 pathway, now missed more than once, as the concept to fix first.

Each round of outside review changed the product too. After round 1 we made the checked question bank the default, added question flagging, spaced repetition and the coach note. After round 2 came signed learner IDs, private demo copies and the full fact-check of the bank. The changes are listed in ROUNDS.md.

Fact-checking the questions

A study tool that teaches a wrong fact is worse than none. Each of the 130 bank questions has a source page whose text states the marked answer, a concept check (one defensible answer, every distractor wrong, nothing outdated), and blind answers from two other models. Both models matched the key on all 130. Three questions were fixed: the Forest (Conservation) Act, 1980 now also carries its 2023 name, Van (Sanrakshan Evam Samvardhan) Adhiniyam; the RBI inflation-target explanation adds the March 2026 renewal; and one concept label was renamed to match what its question tests.

Limits

  • Fresh AI questions are checked by a second model only, not against sources, and the quiz says so.
  • Anyone who knows a learner ID can read that learner's plan, so treat the ID like a password.
  • Memory writes are real mainnet writes, so saves are rate-limited.
  • Free AI models are sometimes busy. The plan never depends on them, and the coach note falls back to a short note written in code.
